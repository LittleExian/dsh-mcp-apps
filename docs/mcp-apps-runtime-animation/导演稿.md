# MCP Apps runtime animation · 分页导演稿

Format: 1600×900 responsive HTML deck · 15 independent pages · replay per page.

每页只讲一个主题。进入页面时自动播放本页动画；翻页不会延续上一页时间轴。最后两页使用真实运行录制，方便把抽象架构与实际结果对应起来。

| 页 | 主题 | 独立动画重点 | 核验内容 |
|---|---|---|---|
| 01 | 全局架构 | 模型入口路径与 App 回调路径依次亮起 | DSH、Host、Server、AppBridge、App 的边界 |
| 02 | DSH 启动 | `dsh web` 到工具注册逐节点出现 | profile、插件 `apply(ctx)`、MCP initialize、tools/list |
| 03 | 入口工具 | 用户意图与 `show-trending` 调用包进入 Server | model-visible 工具、UI resource metadata |
| 04 | 结果保留 | CallToolResult 分流为 model-safe result 与 retained result | `callToken` 的来源与用途 |
| 05 | 打开卡片 | `apps/open`、`resources/read`、`sessionId` 顺序完成 | 卡片不能自行选择服务器 |
| 06 | 双层沙箱 | 外层代理先出现，内层 MCP App 后出现 | opaque origin、nonce、CSP、navigation revoke |
| 07 | AppBridge | initialize 到 sizeChanged 的消息序列 | Host SDK 与 App SDK 的协议握手 |
| 08 | App 交互 | 光标点击真实 GitHub Trending 的 Today | `callServerTool(refresh-trending)` |
| 09 | Host 校验 | 六项能力门依次通过 | session、server、visibility、resource、boundary、limits |
| 10 | Server 执行 | 请求沿 AppBridge → Host → MCP Server 流动 | App-visible tool 仍由原 Server 执行 |
| 11 | 状态更新 | App 状态更新，模型结果保持静止 | App 回调不写入模型工具事件流 |
| 12 | 职责拆分 | Host 与 MCP Server/App 两列分别显影 | 插件承载能力与业务扩展边界 |
| 13 | WiseWork 链路 | OpenCode 到 DTS Server 的七段模拟链路依次出现 | ACP、Runtime Broker、Session Manager、IPC、沙箱、AppBridge |
| 14 | DSH 实录 | 自动播放真实 DSH GitHub Trending 调用 | Prompt → Tool → App → Today 回调 |
| 15 | WiseWork 实录 | 循环播放此前 DTS 表单测试 GIF | Open → Fill → Submit → mock ticket |

## 控制

- `←` / `Page Up`：上一页
- `→` / `Page Down`：下一页
- `R`：重播当前页
- `O`：打开或关闭 15 页总览
- `Esc`：关闭总览

## 录制来源

- DSH：本地 `deepseek-harness` 的 `web` profile，加载 `@exian/dsh-mcp-apps` 和 GitHub Trending MCP Server 后录制。
- WiseWork：仓库内的 `wisework-dts-test.gif`，由既有测试录制裁切到应用区域，对应 OpenCode 工具事件、Runtime Broker、双层 iframe 与 DTS MCP App 链路。
